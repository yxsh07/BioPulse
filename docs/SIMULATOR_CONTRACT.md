# Simulator integration contract for backend and database owners

The implementation in `org.biopulse.simulation.bidmc` owns BIDMC CSV parsing and historical source import orchestration. It uses the shared `ProvenanceDao`, `RegistryDao`, `MeasurementDao`, `Measurement`, and `WaveformChunk` contracts; no simulator-specific DAO is introduced. Flyway `V7` adds additive scenario metadata to the shared `simulation_sessions` table. Historical import does not emit live alerts. The existing shared replay service uses authenticated `MeasurementIngestionService` to emit alerts and WebSocket events when playback reaches each source time.

## Import route (implemented)

`BidmcDatasetController` exposes the authenticated ADMIN `POST /api/v1/datasets/bidmc/import` route accepting `recordingId` (`bidmc_##`), `ecgLead` (`II`, `V`, `AVR`), `admissionId`, and device IDs for `ECG`, `PPG`, `RESP`, `HR`, `PULSE`, `RR`, `SPO2`. The server resolves files under `BIOPULSE_BIDMC_DATASET_ROOT`, never an arbitrary browser-supplied filesystem path, and calls `BidmcImportService.importRecording`. The import is transactional and writes numeric rows in batches of 500. The shared `ProvenanceDao` writes a stable `externalRecordingId`, so repeat imports fail the database uniqueness constraint and return a conflict. Import failures are transactional; no partial source is presented as replay-ready.

The operator console in `web-simulator/` exposes this workflow: recording ID, ECG lead, active admission, and per-channel device mapping. It preselects the first capable visible device and leaves assignment/capability validation to the backend. The console refreshes recordings after a successful import and selects the new recording for session creation.

`BidmcImportService` anchors source-relative seconds to `2000-01-01T00:00:00Z` solely because the shared recording/measurement DTOs require `Instant` and MySQL `TIMESTAMP` excludes the first second of 1970. The provenance explicitly says this is an offset anchor, not original acquisition wall time. The demo admission association is artificial. BIDMC `Fix.txt` retains the original subject pseudonym. CSV `II`, `V`, or `AVR` is used for ECG; `PLETH` maps to PPG; `RESP` maps to respiration waveform; numeric `RESP` maps to RR. The corresponding published WFDB header expresses ECG in mV; the shared DTO uses `a.u.` for PPG and respiratory waveforms. Numeric blanks remain `null` with `MISSING` quality. Waveform blanks are omitted, preserving gaps rather than drawing fabricated samples.

## Replay integration (implemented)

Existing `POST /api/v1/simulation-sessions` and `POST /{id}/start|pause|resume|stop` are authoritative. `ReplayClock` supplies the monotonic source cursor, speed validation and pause/resume re-anchoring, and `SimulationScheduler` calls `SimulationService.tick` every second for running sessions. Each tick reads at most 1001 scalar rows and 1001 waveform chunks over a bounded window and advances the transactional cursor only after ingestion succeeds. Sessions have independent in-memory clocks. The accepted speed set for the console is `0.5`, `1`, `2`, `5`, `10`. While a replay session is selected, the console follows replay WebSocket events instead of the global latest-measurement endpoint, which may contain newer fixture timestamps.

## Scenario integration (implemented)

`POST /api/v1/simulation-sessions` accepts an optional `scenario` object with `mode`, `fromSeconds`, `toSeconds`, and `magnitude`. The durable columns are `scenario_mode`, `scenario_from_seconds`, `scenario_to_seconds`, and `scenario_magnitude` (Flyway `V7`). `GET /api/v1/simulation-sessions` lists sessions in the caller's admission scope, newest first, and every session response includes `createdAt` plus the scenario definition. Scenario parameters are fixed at creation, like speed.

`ScenarioTransformer` implements deterministic transformations for `NORMAL`, `ABNORMAL_DEMO`, `SENSOR_OFFLINE`, `MISSING_DATA`, `NOISY_SIGNAL`, and `DELAYED_TELEMETRY`. Replay applies them at tick time through `ScenarioReplay`, converting only the session's output source/recording; imported rows remain untouched. Numeric and waveform quality labels, missing spans, and deterministic noise follow the transformer. The output source uses `SourceType.SIMULATION` with `SYNTHETIC_CLINICAL` provenance when a non-normal mode is selected, records the range and magnitude, and keeps original source-relative observation instants. `DELAYED_TELEMETRY` records the requested delay as the scenario magnitude but intentionally does not alter source timestamps or values; it is a labeled scenario, not a transport-delay simulator. Device disconnect must still use the shared device state APIs.

Additional dataset adapters require separate contracts: Synthea and PhysioNet Sepsis Challenge are tabular and must not create ECG/PPG/respiration waveforms. VitalDB can carry sampled signals, but channel availability, rate, units, and license differ by case. No adapter may infer absent channels.
