# Simulator integration contract for backend and database owners

The implementation in `org.biopulse.simulation.bidmc` owns BIDMC CSV parsing and historical source import orchestration. It uses the shared `ProvenanceDao`, `RegistryDao`, `MeasurementDao`, `Measurement`, and `WaveformChunk` contracts; no simulator-specific DAO or migration is introduced. Historical import does not emit live alerts. The existing shared replay service uses authenticated `MeasurementIngestionService` to emit alerts and WebSocket events when playback reaches each source time.

## Required import route

Backend owner: expose an authenticated ADMIN `POST /api/v1/datasets/bidmc/import` route accepting `recordingId` (`bidmc_##`), `ecgLead` (`II`, `V`, `AVR`), `admissionId`, and device IDs for `ECG`, `PPG`, `RESP`, `HR`, `PULSE`, `RR`, `SPO2`. The server must resolve files under a configured dataset root, never an arbitrary browser-supplied filesystem path. Call `BidmcImportService.importRecording` and return its `ImportResult`. The import is transactional and writes numeric rows in batches of 500. The shared `ProvenanceDao` writes a stable `externalRecordingId`, so repeat imports fail the database uniqueness constraint. Report that as a conflict. Record import progress and failure before presenting the source as replay-ready.

`BidmcImportService` anchors source-relative seconds to `2000-01-01T00:00:00Z` solely because the shared recording/measurement DTOs require `Instant` and MySQL `TIMESTAMP` excludes the first second of 1970. The provenance explicitly says this is an offset anchor, not original acquisition wall time. The demo admission association is artificial. BIDMC `Fix.txt` retains the original subject pseudonym. CSV `II`, `V`, or `AVR` is used for ECG; `PLETH` maps to PPG; `RESP` maps to respiration waveform; numeric `RESP` maps to RR. The corresponding published WFDB header expresses ECG in mV; the shared DTO uses `a.u.` for PPG and respiratory waveforms. Numeric blanks remain `null` with `MISSING` quality. Waveform blanks are omitted, preserving gaps rather than drawing fabricated samples.

## Replay and scenario routes still needed

Existing `POST /api/v1/simulation-sessions` and `POST /{id}/start|pause|resume|stop` are authoritative. `ReplayClock` provides the monotonic source cursor, speed validation and pause/resume re-anchoring for the backend owner to wire into the shared scheduler. The existing fixed-delay one-second tick advances by exactly `speed` seconds per execution, so processing delays cause wall-clock drift. Five sessions need independent cursors and bounded work per tick. The accepted speed set for the console is `0.5`, `1`, `2`, `5`, `10`.

`ScenarioTransformer` implements deterministic in-memory transformations for `NORMAL`, `ABNORMAL_DEMO`, `SENSOR_OFFLINE`, `MISSING_DATA`, `NOISY_SIGNAL`, and `DELAYED_TELEMETRY`, returning a synthetic label and modification log. Delayed telemetry returns the requested delay for the publisher to schedule; it does not change source timestamps. Before exposing a mode selector, agree a DTO and route. Each altered output needs `SourceType.SIMULATION`, a durable modification log with parameters, an artificial quality/provenance label, and distinct original offset versus display/receipt time. Device disconnect must use shared device state APIs. The backend and database owners should define durable session metadata for mode and parameter log. The simulator UI will only expose modes after these shared contracts exist.

Additional dataset adapters require separate contracts: Synthea and PhysioNet Sepsis Challenge are tabular and must not create ECG/PPG/respiration waveforms. VitalDB can carry sampled signals, but channel availability, rate, units, and license differ by case. No adapter may infer absent channels.
